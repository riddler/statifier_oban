# Scoped Timer Keys Implementation Plan

## Overview

Derive the two scoped keys a durable-timer store needs - the cancellation key
`{session scope, send_id}` and the dedup key
`{session scope, send_id, macrostep, microstep, round, c_index, owner}` - as
pure functions over `%Statifier.Effect.SendDelayed{}` and
`%Statifier.Effect.Cancel{}`, with `scope` a mandatory argument that is never
derived. No Oban dependency, so this does not wait on the runtime-shape
decision in sob-2hx.2.

Beads issue: `sob-2hx.1`

## Current State Analysis

`lib/` holds only the generated `lib/statifier_oban.ex` (a `hello/0`
placeholder) and `test/` only `test/statifier_oban_test.exs`. This plan
therefore establishes the module namespace and file layout for the timer half
of the package.

What exists to build on:

- The gate is wired: `.quality.exs` (ExQuality, credo `--strict`,
  `warnings_as_errors`, dialyzer, coverage), `mix quality` / `mix quality
  --profile loop`, coverage minimum 90% (`coveralls.json`).
- `mix.exs:34` already puts `test/support` on `elixirc_paths(:test)`, but the
  directory does not exist yet; `coveralls.json` already excludes it.
- `deps/statifier` is vendored, so the real struct shapes are readable and
  `Statifier.Effect.SendDelayed` / `Statifier.Effect.Cancel` can be aliased
  and pattern-matched directly. `:statifier` is a runtime dependency of this
  package (`mix.exs:39`), so matching on those structs costs nothing extra.
- No property-testing library is in `mix.exs`. The bead asks for
  "property-style tests", so one is added here (see Phase 2).

What is missing: everything else. There is no store, no subscriber, no Oban
wiring, and no ADR/decision directory in this repo yet (sob-2hx.2 owns that
choice).

## Desired End State

A pure module, `StatifierOban.Timer.Key`, that turns a stored effect plus a
caller-supplied scope into one of two key structs, plus a test suite that
pins the collision behavior ADR-0054 decision 3 and
`docs/durable-timers.md` ("Keying your store") describe - including the one
collision that is documented as residual rather than fixed.

Verified by: `mix quality` green, the new module reachable with no Oban or
Ecto process running (it has no such dependency), and the property tests
below passing over generated inputs.

### Key Discoveries:

- `%SendDelayed{}` fields, exactly (`deps/statifier/lib/statifier/effect/send_delayed.ex:26-53`):
  `event`, `target`, `type`, `data`, `send_id`, `delay_ms`, `c_index`,
  `owner`, `macrostep`, `microstep`, `round`, `id_from_author?`.
  `@enforce_keys [:event, :delay_ms, :macrostep, :microstep, :round]`.
  `send_id` is `String.t() | nil`; `c_index` is `non_neg_integer() | nil`;
  `owner` is `Statifier.Machine.Content.owner() | nil`.
- `%Cancel{}` fields, exactly (`deps/statifier/lib/statifier/effect/cancel.ex:20-29`):
  `send_id`, `c_index`, `owner`, `macrostep`, `microstep`, `round`.
  `@enforce_keys [:send_id, :macrostep, :microstep, :round]`; `send_id` is
  `String.t()` (not nilable here).
- `owner` is a tuple union, not an atom
  (`deps/statifier/lib/statifier/machine/content.ex:57-61`):
  `{:onentry, non_neg_integer(), non_neg_integer()} | {:onexit, ...} |
  {:transition, non_neg_integer()} | {:finalize, non_neg_integer(),
  non_neg_integer()}`. Generators and specs must reflect that shape.
- Scoping is mandatory, not advisory: `send_counter` restarts at 0 per
  `%MachineState{}` (ADR-0035), so `send_1` from two runs collides in a
  shared store (`deps/statifier/docs/adr/0054-durable-timers-consume-the-effect-vocabulary.md`,
  decision 3; `deps/statifier/docs/durable-timers.md`, "Keying your store").
  The library cannot supply the scope - it has no view of the host store - so
  it is an argument, never a derivation.
- The cancellation key legitimately matches more than one row: spec 6.3
  cancels every timer under a sendid, and an author-written `id` is reused
  verbatim without advancing the counter, so one `<send id="x" delay="...">`
  executed twice yields two rows under one `send_id`. A cancel matching
  nothing is a no-op, not an error.
- `c_index` and `owner` are mandatory dedup-key members: without them, two
  `<send id="x" delay="...">` in one `<onentry>` share all five
  scope/id/counter fields and would collapse into one row.
- The `<foreach>` residual is real and unsolved upstream: the same static
  `c_index` list re-executes per iteration, so an author-written id inside a
  `<foreach>` body yields byte-identical keys per iteration. ADR-0054 states
  the workaround is on the document author's side. Our tests characterize the
  collision rather than pretending to fix it.
- Route filtering is not this bead's job. ADR-0054 decision 2 and ADR-0055
  restrict durable scheduling to sends whose target is absent or `:self`, but
  that filter belongs in the effect consumer (sob-2hx.3), not in a keying
  function.

## What We're NOT Doing

- **No Oban, Ecto, or storage code.** No job args, no unique options, no
  serialization of a key to JSON or to a string. The storable encoding
  depends on the runtime-shape decision sob-2hx.2 owns; encoding here would
  pre-empt it and drag Oban into a bead the bead text explicitly keeps free
  of it. sob-2hx.3 adds the encoding against whatever sob-2hx.2 decides.
- **No target/route filtering** (`target == nil` / `Statifier.Send.Target.parse/1`).
  That is the consumer's gate per ADR-0054 decision 2 and ADR-0055, and
  putting it in a keying function would make the function silently refuse to
  key an effect a caller legitimately stored.
- **No fire-time computation** from `delay_ms`. The clock is the scheduler's,
  and a key derivation that touched a clock would stop being deterministic -
  which is the whole property being bought here.
- **No liveness checking** (ADR-0054 decision 4). That is sob-2hx.5.
- **No fix for the `<foreach>` residual.** The library has no per-iteration
  ordinal on `%SendDelayed{}` to key from; inventing one host-side (a counter,
  a timestamp) would break determinism across a re-executed drive, which is
  what makes the dedup key sound in the first place. Documented and tested as
  a known collision instead.
- **Not removing the `StatifierOban.hello/0` placeholder** or its doctest.
  It is unrelated to this bead, and deleting it in a keying commit is noise.

## Implementation Approach

Two modules under a `StatifierOban.Timer` namespace, both pure:

- `StatifierOban.Timer.CancellationKey` and `StatifierOban.Timer.DedupKey` -
  the key structs.
- `StatifierOban.Timer.Key` - the derivation functions.

Keys are structs rather than bare tuples. Equality and map-key semantics are
identical either way, but `@enforce_keys` gives the mandatory-scope rule
structural teeth, and a named seven-field struct beats a seven-tuple for a
reader and for pattern matches downstream. The bead's `{scope, send_id, ...}`
notation names the components, not the term representation.

Derivation returns `{:ok, key} | {:error, reason}` per the project's
errors-are-events convention: no rescue-to-default, no silently substituted
scope. Two error reasons, both structural:

- `:invalid_scope` - scope is not a non-empty binary (covers `nil`, `""`, and
  any non-binary a caller passes by accident).
- `:missing_send_id` - `%SendDelayed.send_id` is `nil`. The struct's own type
  allows it, and a key with a `nil` id is not addressable by any later
  cancel, so it is an error rather than a key. (`%Cancel.send_id` is
  non-nilable, but the same guard runs so a hand-built struct cannot slip
  through.)

Scope is the first argument, matching the project's "state/session first"
threading convention, and has no default - a defaulted scope is exactly the
derivation the ADR forbids.

#### 1. Key structs

**File**: `lib/statifier_oban/timer/cancellation_key.ex`
**Changes**: New struct, both fields enforced.

```elixir
defmodule StatifierOban.Timer.CancellationKey do
  @moduledoc """
  `{session scope, send_id}` - the key a cancel addresses.

  Deliberately not unique: spec 6.3 cancels every delayed send under a
  sendid, and an author-written `id` is reused verbatim without advancing
  `send_counter`, so one `<send id="x" delay="...">` executed twice stores
  two rows under one key. A cancel matching nothing is a no-op, not an
  error (ADR-0054 decision 3).
  """

  @enforce_keys [:scope, :send_id]
  defstruct [:scope, :send_id]

  @type t :: %__MODULE__{scope: String.t(), send_id: String.t()}
end
```

**File**: `lib/statifier_oban/timer/dedup_key.ex`
**Changes**: New struct, all seven fields enforced (`c_index` and `owner`
may hold `nil` values, but the caller must have supplied them from a stored
effect rather than omitting them).

```elixir
defmodule StatifierOban.Timer.DedupKey do
  @moduledoc """
  `{session scope, send_id, macrostep, microstep, round, c_index, owner}` -
  read off the stored `%Statifier.Effect.SendDelayed{}` (ADR-0054
  decision 3).

  Every component is a deterministic counter or a static content position,
  stamped as of scheduling rather than firing (ADR-0046), so re-executing
  the same drive after a crash rebuilds a byte-identical key. `c_index` and
  `owner` are mandatory members, not decoration: without them two
  `<send id="x" delay="...">` in one `<onentry>` collapse into one row.
  """

  alias Statifier.Machine.Content

  @enforce_keys [:scope, :send_id, :macrostep, :microstep, :round, :c_index, :owner]
  defstruct [:scope, :send_id, :macrostep, :microstep, :round, :c_index, :owner]

  @type t :: %__MODULE__{
          scope: String.t(),
          send_id: String.t(),
          macrostep: non_neg_integer(),
          microstep: non_neg_integer(),
          round: non_neg_integer(),
          c_index: non_neg_integer() | nil,
          owner: Content.owner() | nil
        }
end
```

#### 2. Derivation

**File**: `lib/statifier_oban/timer/key.ex`
**Changes**: New module. Three public functions, all pure, `@spec` on each,
scope first.

```elixir
defmodule StatifierOban.Timer.Key do
  @moduledoc """
  Derives the two scoped keys a durable-timer store needs, per ADR-0054
  decision 3 and `docs/durable-timers.md` ("Keying your store") in
  statifier-ex.

  `scope` is always an argument and never derived: `send_counter` restarts
  at 0 for every chart run (ADR-0035), so `send_1` from one run addresses
  the same row as `send_1` from an unrelated run unless the store keeps
  them apart. It is `ctx.session_id` (spec 5.10's `_sessionid`) for a live
  session, or the host's own durable run id for a process-less host.
  """

  alias Statifier.Effect.{Cancel, SendDelayed}
  alias StatifierOban.Timer.{CancellationKey, DedupKey}

  @type scope :: String.t()
  @type error :: :invalid_scope | :missing_send_id

  @spec cancellation_key(scope(), SendDelayed.t() | Cancel.t()) ::
          {:ok, CancellationKey.t()} | {:error, error()}
  def cancellation_key(scope, effect)

  @spec dedup_key(scope(), SendDelayed.t()) ::
          {:ok, DedupKey.t()} | {:error, error()}
  def dedup_key(scope, send_delayed)

  @spec cancels?(CancellationKey.t(), DedupKey.t()) :: boolean()
  def cancels?(cancellation_key, dedup_key)
end
```

- `cancellation_key/2` accepts either effect, because a store needs the key
  both when writing a row (from `%SendDelayed{}`) and when a cancel arrives
  (from `%Cancel{}`). Both clauses read only `send_id`.
- `dedup_key/2` accepts `%SendDelayed{}` only. `%Cancel{}` has no `delay_ms`
  and never becomes a stored row; a `Cancel` dedup key would be a term with
  no referent.
- `cancels?/2` answers "does this cancel address that stored row" -
  scope and `send_id` equality, ignoring every position field. It exists so
  sob-2hx.4 has one place stating the many-rows-per-cancel rule instead of
  re-deriving it at the query site.
- Guards: a private `validated_scope/1` returning `{:ok, scope} | {:error,
  :invalid_scope}` (non-empty binary), and a `send_id` guard rejecting `nil`
  with `{:error, :missing_send_id}`. No rescue, no default.

#### 3. Example-based tests

**File**: `test/statifier_oban/timer/key_test.exs`
**Changes**: New. Cases, one assertion shape each, pattern-matched:

- `dedup_key/2` copies all seven components off a fully populated
  `%SendDelayed{}`.
- `dedup_key/2` preserves `nil` `c_index` / `owner` verbatim rather than
  substituting a default.
- `cancellation_key/2` from a `%SendDelayed{}` and from the matching
  `%Cancel{}` produce equal keys.
- `cancellation_key/2` ignores `macrostep` / `microstep` / `round` /
  `c_index` / `owner`.
- Scope `nil`, `""`, and a non-binary each return `{:error, :invalid_scope}`,
  for both functions.
- `%SendDelayed{send_id: nil}` returns `{:error, :missing_send_id}` from both
  functions.
- Calling either function twice with equal inputs returns equal keys
  (determinism, the example-level companion to Phase 2's property).
- `cancels?/2` is true across differing position fields, false across
  differing scope, false across differing `send_id`.

## Phase 2: Property tests for the named collision cases

### Overview

Add StreamData and generators for the two effect structs, then state the
keying rules as properties - including the two collisions the recipe names by
hand: the same `send_id` across runs, and an author-written id executed
twice (in one `<onentry>`, and inside a `<foreach>`).

StreamData is the choice because the bead asks for property-style tests and
the collision claims are universally quantified ("no two runs collide", "the
key is injective on its components"); an example table can illustrate those
but cannot state them. It is `only: [:dev, :test], runtime: false`, so it
does not reach a host application.

The fields no key reads get deliberately small generators, because nothing

#### 3. Properties

**File**: `test/statifier_oban/timer/key_property_test.exs`
**Changes**: New. `use ExUnitProperties`. Properties:

1. **Determinism.** For any scope and effect, two derivations are equal, and
   two structurally equal effects built independently give equal keys. (Pure:
   no clock, no pid, no CSPRNG - the claim ADR-0054 decision 3 rests on.)
2. **Scope separates runs.** For any effect and any two distinct scopes, the
   dedup keys differ and the cancellation keys differ. This is the recipe's
   "same `send_id` across runs" case: `send_counter` restarts at 0 per run,
   so the generated effects are deliberately allowed to be identical apart
   from scope.
3. **Dedup key injectivity.** Two effects under one scope produce equal dedup
   keys if and only if all seven components are equal. This is the property
   that makes at-least-once redelivery safe and simultaneously proves
   `c_index` and `owner` are load-bearing - specialized into a case where the
   two effects share scope, `send_id`, `macrostep`, `microstep`, and `round`
   and differ only in `c_index` or only in `owner` (the "two
   `<send id="x">` in one `<onentry>`" case), where the keys must differ.
4. **Cancellation key ignores position.** Two effects sharing scope and
   `send_id` but generated independently in every other field share a
   cancellation key, and `cancels?/2` holds between that key and both dedup
   keys - the "may legitimately match more than one stored row" rule.
5. **Cancel/SendDelayed agreement.** For any scope and any `%SendDelayed{}`,
   the cancellation key derived from it equals the one derived from a
   `%Cancel{}` carrying the same `send_id` and arbitrary other fields.
6. **Scope is mandatory.** For any effect, `nil`, `""`, and generated
   non-binary scopes all return `{:error, :invalid_scope}`; no generated
   input produces a key with a `nil` or empty scope.
7. **`<foreach>` residual, characterized.** For any scope and any
   `%SendDelayed{}` with an author-written id (`id_from_author?: true`),
   replaying the *same* effect struct - which is what a `<foreach>` body
   emits per iteration, same `c_index`, same `owner`, same microstep,
   same author id - yields identical dedup keys. Asserted as equality with a
   comment citing ADR-0054's "Residual collision, stated honestly" and the
   author-side workaround (omit the hand-written `id`), and paired with the
   contrasting case: the same effect with generated ids (`send_1`, `send_2`)
   yields distinct keys.

Sabotage note: property tests are sabotage-checked the same way as the
example tests - for property 3, dropping `c_index` from the struct must turn
it red; for property 2, dropping `scope` must.

## Testing Strategy

### Unit Tests:

- `test/statifier_oban/timer/key_test.exs` - example-based: field-by-field
  derivation, `nil` `c_index`/`owner` preserved, scope error paths (`nil`,
  `""`, non-binary), `missing_send_id`, `cancels?/2` truth table.
- `test/statifier_oban/timer/key_property_test.exs` - the seven properties
  above, over generated effects.
- Key edge cases: `send_id: nil` on `%SendDelayed{}` (the struct permits it,
  the store cannot address it); `c_index: nil` and `owner: nil` (permitted,
  and must not be silently defaulted, or two distinct sends would merge);
  counters at 0 (a fresh run, where cross-run collision is most likely);
  identical effects differing only by scope; identical effects in every
  field (the `<foreach>` residual).

### Manual Testing Steps:

1. `iex -S mix`, build a `%Statifier.Effect.SendDelayed{}` by hand and call
   both derivations; confirm the returned structs carry exactly the stored
   values and nothing computed.
2. Call `dedup_key/2` twice with the same input in the same session and in a
   fresh `iex`; confirm the two keys compare equal - determinism across
   process boundaries, which is what surviving a restart means.
3. Read the two moduledocs against
   `deps/statifier/docs/adr/0054-durable-timers-consume-the-effect-vocabulary.md`
   decision 3 and confirm every claim is one the ADR makes.

## Open Questions

Recorded rather than resolved, because no human was available during
planning. None blocks implementation; each names the decision taken by
default and who would revisit it.

1. **Structs versus bare tuples for the keys.** Taken: structs, for
   `@enforce_keys` and readable seven-field pattern matches. If sob-2hx.3
   finds tuples fit an Oban unique-args encoding better, converting is a
   mechanical change confined to these three modules.
2. **Where `cancels?/2` belongs.** It is included here so the
   many-rows-per-cancel rule has one statement. If sob-2hx.4 ends up
   expressing cancellation as a store query instead, `cancels?/2` may become
   dead code and should be deleted rather than kept for symmetry. Plan review
   flagged it as speculative surface for a bead titled "scoped keys"; kept
   anyway, because the many-rows-per-cancel rule is a keying rule and this is
   the module that states the keys, and because it is fully covered by its
   own tests either way. Delete it in sob-2hx.4 if no caller appears.
3. **StreamData as the property library.** Taken: StreamData, the de facto
   Elixir default. If the project later prefers a different one, the
   generators are one small file.
4. **Whether `{:error, :missing_send_id}` is right for `send_id: nil`.** The
   upstream type permits `nil`, and it is unclear whether a core-produced
   `%SendDelayed{}` can actually carry one in practice. Erroring is the safe
   reading; if it turns out to be unreachable, the clause stays as a guard
   and the test documents the intent.
